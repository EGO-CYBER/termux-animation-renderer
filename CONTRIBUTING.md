# 🤝 Contributing

Спасибо, что хотите помочь проекту. Он young и активно растёт — любой вклад ценен.

## Что здесь уместно

- 🐛 **Баги** — особенно падения Chromium, ошибки рендера, неверные кадры
- 🧹 **Мелкие правки** — опечатки в README, неточности в описаниях
- ⚡ **Ускорение** — узкие места в конвейере кадров, лишние копирования
- 🎨 **Новые примеры** анимаций в `examples/`
- 📖 **Документация** — особенно примеры под типичные сбои

## Перед тем как открыть issue

1. Поищите в [существующих issue](https://github.com/EGO-CYBER/termux-animation-renderer/issues) — возможно, это уже обсуждали.
2. Воспроизведите проблему и соберите диагностику:

   ```bash
   anim selftest
   TR_DEBUG=1 anim render animation.html
   ```

   Лог появится в `~/tr-debug.log` — **приложите его к issue**, он почти всегда содержит ответ.

3. Для бага заполните [bug_report.yml](.github/ISSUE_TEMPLATE/bug_report.yml), для идеи — [feature_request.yml](.github/ISSUE_TEMPLATE/feature_request.yml).

## Локальная разработка

```bash
git clone https://github.com/EGO-CYBER/termux-animation-renderer.git
cd termux-animation-renderer
bash install.sh          # поставит зависимости и создаст команду anim
```

### Проверки перед отправкой

```bash
npm test                 # тесты
npm run check            # синтаксис главного модуля
for f in src/*.js; do node --check "$f"; done
bash -n install.sh && bash -n anim
```

Ровно эти проверки выполняет CI, поэтому локальный прогон избавит от лишнего прогона пайплайна.

## Как писать код

- **Node.js ≥ 18**, ES-модули (`"type": "module"`).
- **Без новых зависимостей.** В проекте намеренно нет `puppeteer` / `playwright` — Chromium общается напрямую по CDP, а кадры идут в FFmpeg через pipe. Добавление тяжёлой библиотеки ломает главный смысл проекта («всё работает на телефоне»).
- **Комментарии и строки — по-русски**, как в остальном проекте.
- Имена переменных — английские.
- Код — `src/`, тесты — `test/`, примеры — `examples/`.

## Правила рендера

Это не формальность: если кадр зависит от чего-то кроме `time`, результат будет неверным.

Кадр **обязан**:

- ✅ зависеть только от аргумента `time`
- ✅ рисоваться целиком с нуля
- ✅ работать без сети и без CDN

Кадр **не должен**:

- ❌ использовать `Date.now()`, `performance.now()`, `requestAnimationFrame`
- ❌ использовать таймеры, CSS-анимации
- ❌ использовать `Math.random()` без фиксированного seed

`src/lint.js` проверяет это автоматически и ругается понятным текстом.

## Pull Request

1. Создайте ветку от `main`:

   ```bash
   git checkout -b fix/motion-blur
   ```

2. Внесите изменения, закоммитьте осмысленным сообщением (описание «что изменилось», а не «fix»).
3. Обновите [README.md](README.md) или [PROMPT_RU.txt](PROMPT_RU.txt), если изменилось поведение.
4. Откройте PR и заполните шаблон.
5. Дождитесь зелёного CI.

Мелкие правки в текстах можно присылать прямо в `main` — отдельная ветка не обязательна.

## Вопросы, которые стоит задать до PR

- Нужен ли для этого новый модуль, или хватит правки существующего?
- Не сломается ли это на устройстве с 2 ГБ ОЗУ?
- Покрыто ли изменение тестом, и если нет — почему?
- Не появляется ли здесь ожидание, которое может повиснуть на рендере?
