# Промт для генерации animation.html

Это **техническая методичка**, а не творческое ТЗ. Она описывает только формат файла и жёсткие ограничения рендерера. Стиль, сюжет, темп и подача целиком определяются вашим описанием в конце промта. Поэтому модель не навязывает «фирменный» стиль.

## Где и как делать

1. Возьмите любую сильную модель для кода (Claude, ChatGPT, Gemini,и т.п.). Лучше выбирать режим с длинным ответом или рассуждением: файл получается большим.
2. Скопируйте блок промта ниже, впишите описание в последней строке и отправьте одним сообщением.
3. Сохраните ответ (только код) как `animation.html`. Удобно: вставить в редактор Termux (`nano animation.html`) или сохранить из чата в Загрузки.
4. Проверьте кадр: `anim preview animation.html`. Если что-то не так, опишите модели, что изменить.
5. Рендер: `anim render animation.html -o имя`.
6. **Если программа выдала ошибку**, она печатает готовый «Текст для нейросети» (и копирует его в буфер обмена). Вставьте его в тот же чат: модель исправит файл.

Чем подробнее описание (жанр, настроение, цвета, темп, референсы, что должно происходить в начале, середине и конце), тем точнее и разнообразнее результат.

ПРОМТ:
```
ТЫ — JAVASCRIPT-РАЗРАБОТЧИК.

Создай программную анимацию по описанию в конце этого сообщения для
Termux Animation Renderer. Рендерер открывает твой HTML в Chromium,
для каждого кадра вызывает window.renderFrame(time), делает скриншот и
собирает кадры в MP4. Кадры рендерятся ПАРАЛЛЕЛЬНО в нескольких вкладках
и В ПРОИЗВОЛЬНОМ ПОРЯДКЕ, поэтому кадр обязан зависеть только от time.

ВЕРНИ один полностью готовый файл animation.html одним блоком кода.
Без пояснений, без псевдокода, без TODO, без пропусков вида "...".

1. ОБЯЗАТЕЛЬНО, в начале первого <script>:

    window.VIDEO = { width: 1920, height: 1080, fps: 30, duration: 15 };

   Подставь значения под задачу (width/height — целые числа; duration —
   секунды). Пользователь ничего из этого не вводит: рендерер читает
   объект сам. Необязательное поле audio — путь к звуковому файлу
   рядом с html, только если он явно нужен: audio: "music.mp3".

2. ОБЯЗАТЕЛЬНО:

    window.renderFrame = function (time) { /* полностью отрисовать кадр */ };

   time — секунды (0, 1/fps, 2/fps ... до duration). Функция сама
   очищает и полностью перерисовывает сцену. Может быть async.

3. ДЕТЕРМИНИЗМ. renderFrame(2.5) всегда даёт один и тот же кадр, сколько
   бы раз и в каком бы порядке его ни вызывали. Позиции и состояния
   считай ФОРМУЛАМИ от time:

    x = 100 + time * 200;      // правильно
    x += 5;                     // НЕПРАВИЛЬНО: копит состояние между кадрами

   ЗАПРЕЩЕНО как источник времени или состояния: Date.now(), new Date(),
   performance.now(), requestAnimationFrame, setTimeout, setInterval,
   CSS @keyframes / animation / transition, <video>, <audio>,
   Math.random() без seed.

4. СЛУЧАЙНОСТЬ. Только детерминированный генератор с фиксированным seed.
   Все случайные параметры (позиции, размеры, фазы) сгенерируй ОДИН РАЗ
   при загрузке скрипта и храни в массивах; внутри renderFrame используй
   только их вместе с time. Пример генератора:

    function makeRng(seed) {
        let s = seed % 2147483647; if (s <= 0) s += 2147483646;
        return () => (s = (s * 16807) % 2147483647, (s - 1) / 2147483646);
    }

5. ОФЛАЙН. Никакого интернета: без <script src="https://...">, fetch,
   CDN, внешних шрифтов, картинок и стилей. Шрифты — только системные
   (sans-serif, serif, monospace). Картинки и звуки, если нужны, —
   встроенные data:URI или нарисованные кодом. Three.js и другие
   библиотеки допустимы, только если их код вставлен в файл целиком.

6. ТЕХНОЛОГИЯ выбирай под задачу:
   - Canvas 2D: 2D, частицы, персонажи, графики, эффекты;
   - SVG: векторная графика, схемы, интерфейсы (обновляй атрибуты
     из time, не используй SMIL/CSS-анимацию);
   - WebGL: 3D и сложные эффекты. Контекст создавай с
     { preserveDrawingBuffer: true, antialias: true }. Рендерер работает
     без GPU (программный WebGL), поэтому держи сцену лёгкой.
   Размер canvas/SVG равен window.VIDEO.width x height. Стили страницы:
   margin: 0; overflow: hidden; фон под сцену.

7. ПРОИЗВОДИТЕЛЬНОСТЬ. Тяжёлое (массивы частиц, градиенты, геометрию,
   предрасчёты) создавай один раз при загрузке. В renderFrame только
   вычисляй положение по time и рисуй. Избегай огромных теней/blur на
   весь кадр в каждом кадре: рендер идёт на телефоне.

8. ВРЕМЯ ПО ЭТАПАМ (по желанию). Если сцена состоит из этапов, задай
   границы константами и определяй активный этап через time:

    const SCENES = [{ start: 0, end: 5 }, { start: 5, end: 12 }];
    const scene = SCENES.find(s => time >= s.start && time < s.end) || SCENES[SCENES.length - 1];

   Количество, содержание и характер этапов определяются только
   описанием видео ниже.

ПЕРЕД ОТВЕТОМ ПРОВЕРЬ:
[ ] есть window.VIDEO и window.renderFrame(time)
[ ] нет Date.now/performance.now/Math.random без seed/rAF/таймеров/CSS-анимаций
[ ] нет внешних ресурсов и CDN
[ ] нет накопления состояния между вызовами renderFrame
[ ] последний кадр (time близко к duration) корректен, а не пустой
[ ] файл полный, без TODO и заглушек

ОПИСАНИЕ ВИДЕО (стиль, сюжет, настроение, темп, референсы, длительность):

[ВПИШИТЕ СВОЁ ОПИСАНИЕ]
```
